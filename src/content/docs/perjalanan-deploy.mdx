## Sepuluh langkah dari sisimu

Dari kacamata pengguna, perjalanannya seperti ini.

### 1. Masuk

Kamu masuk ke Console pada `app.sakala.dev`. Masuk lewat akun GitHub adalah jalur utamanya, karena Sakala perlu membaca repository-mu.

### 2. Onboarding

Sakala menanyakan hal-hal dasar sekali di awal, supaya tidak perlu ditanyakan berulang di tiap project.

### 3. Membuat project

Project adalah wadah berumur panjang. Ia menyimpan repository yang terhubung, konfigurasi, variabel, alamat, dan seluruh riwayat deployment. Project bukan sekadar satu container yang sedang berjalan.

### 4. Menghubungkan repository

Kamu memilih repository dan branch. Pada tahap awal, yang didukung adalah repository GitHub publik.

### 5. Analisis repository

Sakala membaca isi repository untuk menebak stack, cara build, dan cara menjalankannya. Hasilnya ditampilkan supaya kamu bisa memeriksanya, bukan langsung dipakai diam-diam.

Kalau tebakannya keliru, kamu dapat memperbaikinya. Sakala menampilkan alasan di balik tebakan itu, misalnya:

```txt
Terdeteksi: Laravel
PHP      : 8.x
Builder  : Railpack
Port     : 8080
```

### 6. Konfigurasi

Kamu melengkapi variabel, secret, dan pengaturan lain sebelum deploy pertama. Lihat [Variabel dan Secret](/docs/variabel-dan-secret).

### 7. Deploy

Kamu menekan deploy. Sakala mengantre pekerjaan itu, lalu menjalankannya tahap demi tahap.

### 8. Mengikuti prosesnya

Kamu melihat tahap yang sedang berjalan, bukan sekadar tulisan "sedang memproses". Tiap tahap punya nama, sehingga bila gagal kamu tahu berhenti di mana.

### 9. Membaca log

Log build dan runtime tersedia untuk kamu baca. Secret disensor supaya tidak ikut tercetak.

Kalau gagal, lihat [Ketika Deployment Gagal](/docs/ketika-gagal).

### 10. Membuka alamatnya, lalu redeploy

Aplikasi yang lolos health check mendapat alamat publik. Setelah kamu memperbaiki kode dan push, kamu dapat men-deploy ulang, dan deployment baru tidak langsung menghancurkan yang sedang sehat.

## Yang belum termasuk pada tahap awal

Supaya harapannya tepat, hal-hal berikut sengaja belum masuk lingkup awal: domain sendiri, database terkelola, penyimpanan objek, worker dan cron, workspace tim, environment preview, rollback, serta CLI.

Semuanya tercatat sebagai arah pada [halaman roadmap](/#roadmap), bukan dijanjikan sekarang.
