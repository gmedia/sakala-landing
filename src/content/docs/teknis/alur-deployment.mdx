# Alur Deployment

Console mengirim intent pengguna ke API. API membuat command, lalu agent mengambil pekerjaan secara outbound. Tidak ada jalur yang membiarkan browser menyentuh runtime secara langsung.

## Siklus command

1. Console mengirim permintaan deployment ke API.
2. API memvalidasi permintaan dan menyimpannya sebagai command.
3. Agent melakukan polling terhadap command yang tersedia.
4. Agent melakukan claim sebelum menjalankan pekerjaan.
5. Agent mengirim event dan log yang sudah melalui redaction.
6. Agent melaporkan hasil sukses atau gagal ke API.

Polling hanya menawarkan pekerjaan yang eligible. Agent belum boleh mengeksekusi command sebelum claim atomik berhasil. Command yang sudah diklaim atau selesai tidak dikembalikan lagi sebagai pekerjaan pending biasa.

## State deployment

Sebuah deployment adalah percobaan, bukan objek yang selalu berhasil. Karena itu setiap tahap punya nama sendiri sehingga kegagalan dapat ditunjuk secara spesifik.

Karena tahapnya bernama, pesan kegagalan dapat menyebut tahap mana yang berhenti dan apa yang perlu diperiksa, bukan sekadar `something went wrong`.

Setiap deployment mencatat commit sumber, branch, pemicu, aktor, builder, runtime node, resource yang diminta dan diterapkan, status, event, log, image, route, hasil health check, waktu, serta kategori kegagalan.

## Routing aplikasi

Aplikasi yang berhasil dijalankan dipetakan ke domain `*.run.sakala.dev`. Pada playground lokal, pola yang sama diuji melalui `*.run.sakala.localhost`.

Container aplikasi mengikat alamat loopback, dan Caddy meneruskan hostname publik ke port internal tersebut. Route ditulis sebagai berkas yang divalidasi lebih dulu, baru kemudian dimuat ulang.

## Deployment tidak merusak yang sedang sehat

Sebuah deployment baru tidak seharusnya langsung menghancurkan aplikasi yang sedang berjalan. Arah yang dituju adalah membangun kandidat, menjalankannya, memeriksa route dan health-nya, baru menukar deployment aktif dan memensiunkan yang lama.

MVP boleh memakai versi yang lebih sederhana, tetapi arsitekturnya sengaja tidak menyamakan project dengan satu container yang itu-itu saja.

## Status saat ini

Fondasi MVP agent sudah menyediakan eksekusi Dockerfile dan Railpack serta pembaruan route Caddy secara opt-in. Fitur tersebut belum menjadi layanan hosted publik dan masih membutuhkan integrasi Agent API serta runtime node yang dikonfigurasi untuk pilot.

Detail operating mode dan batas runtime dijelaskan pada [Cara kerja Sakala Agent](/docs/teknis/agent).
