# Sakala Landing Reference Notes

> References are for principles, not visual copying.

Do not recreate another company's layout, copy, animation, or visual identity.

## Daylight

Reference:

```text
https://daylightcomputer.com/
```

Learn:

- worldview before specification;
- mission can create curiosity before features.

Translate for Sakala:

```text
not every completed project becomes present
```

Do not copy the manifesto length or device aesthetic.

## Framework

Reference:

```text
https://frame.work/
```

Learn:

- a belief becomes credible when product structure reflects it;
- openness can be part of product philosophy, not just a badge.

For Sakala, open source connects to `Terang`, learning, inspectability, and contribution.

## Resend

Reference:

```text
https://resend.com/philosophy
```

Learn:

- philosophical principles can use simple words;
- principles should have product consequences.

Example translation:

```text
Terang
→ "Ketika deployment gagal, developer berhak tahu mengapa."
```

## Zed

References:

```text
https://zed.dev/
https://zed.dev/about
```

Learn:

- memorable statement + clear product explanation;
- real product artifacts earn credibility;
- software craft can be identity;
- the user's work should remain the focus.

For Sakala:

The project, not infrastructure, is the protagonist.

## Linear

Reference:

```text
https://linear.app/
```

Learn:

- product UI can be visual material;
- restraint creates confidence;
- focused artifacts beat decorative illustrations.

Do not copy the dark-gradient aesthetic or layout.

## Stripe Press

Reference:

```text
https://press.stripe.com/
```

Learn:

- whitespace gives ideas weight;
- editorial pacing can make technology feel thoughtful.

For Sakala, keep the existing Sakala type/color system rather than copying editorial styling literally.

## Deno / Bun

References:

```text
https://deno.com/
https://bun.sh/
```

Learn:

- code and commands can be visual evidence;
- developer artifacts often explain more than illustration.

For Sakala:

repository, domain, deployment states, and logs should carry visuals.

## Supabase

Reference:

```text
https://supabase.com/
```

Learn:

- open source can be positioned through inspectability and participation;
- concrete proof should accompany open-source claims.

Do not copy its green aesthetic. Sakala already has its own Green Teal and philosophy.

## Mozilla

Reference:

```text
https://www.mozilla.org/mission/
```

Learn:

- mission can remain stable while implementation evolves;
- human outcomes can outlast technical mechanisms.

For Sakala:

Docker, builder technology, and runtime architecture may change.

```text
help work become present
```

should remain.

## Ink & Switch

Reference:

```text
https://www.inkandswitch.com/
```

Learn:

- software can be presented as the result of a way of thinking;
- architecture and research artifacts can make an open project feel serious.

For Sakala:

```text
philosophy → product → architecture → ADR → code
```

should form one intellectual chain.

## Railway / Render / Coolify category lesson

References:

```text
https://railway.com/
https://render.com/
https://coolify.io/
```

The deployment category already competes on:

```text
easy
fast
zero ops
without complexity
self-hosted
```

These can be product values but should not become Sakala's entire identity.

Distinctive Sakala territory:

```text
possibility
presence
understanding
life of a work
continuation
```

## Dieter Rams / restraint

Reference:

```text
https://rams-foundation.org/foundation/design-comprehension/theses/
```

Learn:

- understandability;
- honesty;
- unobtrusiveness;
- as little design as necessary.

A landing can be memorable without becoming a motion demo.

## Reference rule for agents

When using a reference, document:

```text
Reference:
Principle borrowed:
How Sakala translates it:
What is deliberately NOT copied:
```

Never use vague instructions such as:

```text
make this section like Linear
```

## Sakala remains the primary reference

External references help with craft.

They do not define the brand.

The strongest source remains:

```text
Sakala Philosophy
Sakala Vision
Sakala Product Principles
Sakala Design System
```
