# Sakala Landing Voice & Language

> **Sakala speaks in observations, not slogans.**

## 1. Voice

Sakala should sound:

```text
clear
thoughtful
grounded
quietly confident
human
technical when useful
curious
honest
```

It should not sound:

```text
corporate
grandiose
mystical
sales-heavy
hyperactive
academic
juvenile
AI-generated
```

## 2. Language ratio

A useful writing constraint:

```text
70% clear
20% contemplative
10% poetic
```

The landing may make a visitor stop and think.

It must never require them to decode the sentence.

## 3. Copy pattern

Strong Sakala copy often follows:

```text
OBSERVATION
something familiar

      ↓

TENSION
something remains unfinished

      ↓

REVELATION
a clearer way to see it
```

Examples:

> Kode dapat selesai ditulis.  
> Tetapi belum tentu selesai diwujudkan.

> Berjalan di laptop bukan berarti dapat dijangkau.

> Repository menyimpan source.  
> Dunia membutuhkan sesuatu yang dapat dibuka.

> Sederhana tidak harus berarti tersembunyi.

> Karya tidak harus berakhir ketika tugas selesai.

## 4. Words Sakala owns

Prefer vocabulary connected to the project's philosophy:

```text
kemungkinan
wujud
hadir
hidup
karya
source
repository
perjalanan
memahami
terang
tumbuh
berbagi
dipelajari
mencipta
mewujudkan
menjangkau
menjalankan
memperbaiki
melanjutkan
```

Technical vocabulary is welcome when it improves truth:

```text
build
runtime
health check
deployment
logs
port
domain
repository
commit
```

Explain unfamiliar terms when writing for beginner-facing surfaces.

## 5. Generic SaaS vocabulary to avoid

Avoid unless there is a specific, defensible reason:

```text
seamless
effortless
powerful
next-generation
cutting-edge
revolutionary
supercharge
game-changing
world-class
modern platform
developer-first
cloud-native
zero-ops
one-click everything
infinitely scalable
enterprise-grade
```

Test:

> Could this exact sentence appear on Railway, Render, Vercel, Netlify, Coolify, or any random AI SaaS page?

If yes, rewrite it.

## 6. Philosophy must become concrete

Bad:

> Kami percaya pada transparansi.

Better:

> Ketika deployment gagal, developer berhak tahu mengapa.

Then show the failure artifact.

Bad:

> Sakala mengutamakan pengalaman end-to-end.

Better:

> Build berhasil belum berarti perjalanan selesai.

Then show:

```text
Build → Start → Health → Route → Public URL
```

## 7. Tone by context

### Hero

Short, spacious, memorable.

Example:

> **Setiap karya bermula sebagai kemungkinan.**

### Plain product explanation

Unromantic and obvious.

Example:

> Sakala adalah project deployment open-source yang membantu membawa source dari repository menjadi aplikasi yang dapat berjalan, dibuka, dan dibagikan.

This sentence exists to prevent philosophical ambiguity.

### Technical artifacts

Precise, not poetic.

Good:

```text
Health Check Failed
Application did not respond on port 8080.
```

Bad:

```text
Your creation has not yet awakened.
```

Never turn operational errors into poetry.

### Open source

Belief + proof.

Example:

> Yang membantu orang belajar seharusnya dapat ikut dipelajari.

Then:

```text
Source: Public
License: Apache-2.0
```

### CTA

Calm and factual.

Prefer:

```text
Explore Sakala
Read Documentation
Read the Philosophy
View on GitHub
```

Avoid:

```text
Unlock the future
Start your journey
Supercharge your deployment
```

## 8. Indonesian and English

Indonesian is not a translation layer for English.

Write both languages natively.

Example:

English:

> Every repository holds a possibility.

Do not force a literal Indonesian translation:

> Setiap repositori menampung sebuah kemungkinan.

Prefer a natural Sakala line:

> Setiap karya bermula sebagai kemungkinan.

Meaning and voice matter more than word-for-word equivalence.

## 9. Language roles

A useful split:

```text
Narrative voice
→ natural Indonesian / natural English

System artifacts
→ technical interface language, often English

Brand tagline
→ Manifesting Code into Reality.
```

Do not mix languages randomly inside one sentence.

Technical terms commonly used by developers may remain English when Indonesian alternatives feel artificial.

## 10. Address

For Indonesian user-facing copy:

```text
kamu
```

Use sparingly.

The landing does not need to say "kamu" in every paragraph.

## 11. Sentence rhythm

Prefer:

- short sentences around major ideas;
- longer explanatory sentences only after a strong anchor;
- deliberate line breaks;
- one memorable line per chapter.

Avoid:

- three paragraphs before the point;
- stacked metaphors;
- six adjectives;
- em-dash abuse;
- filler words.

## 12. Candidate headline library

These are **directional candidates**, not mandatory final copy.

### Possibility

- Setiap karya bermula sebagai kemungkinan.
- Sebelum hidup, software adalah kemungkinan.
- Kode memberi ide sebuah bentuk.

### Distance

- Tidak semua yang selesai dibuat, selesai diwujudkan.
- Berjalan belum tentu berarti hadir.
- Localhost membuktikan sesuatu bekerja. Bukan bahwa dunia dapat membukanya.

### Threshold

- Di sinilah Sakala berada.
- Dari source menuju sesuatu yang dapat dijangkau.
- Antara repository dan aplikasi yang hidup, ada sebuah perjalanan.

### Manifestation

- Wujud bukan sekadar build yang berhasil.
- Perjalanan belum selesai sampai karya dapat dijangkau.
- Dari source. Sampai hadir.

### Clarity

- Sederhana tidak harus berarti tersembunyi.
- Ketika sesuatu gagal, kamu berhak tahu mengapa.
- Magic boleh terjadi. Misteri tidak harus.

### Life

- Deployment bukan akhir perjalanan.
- Karya yang hidup dapat melahirkan karya berikutnya.
- Setelah hadir, sebuah karya dapat terus tumbuh.

### Ending

- Apa yang akan kamu wujudkan?
- Dari kemungkinan, menuju sesuatu yang nyata.
- Here it is.

## 13. Copy quality checklist

Before accepting a line:

- Is it understandable in one read?
- Is it true?
- Is it specific to Sakala's worldview?
- Does it avoid unsupported product claims?
- Would a beginner still understand the idea?
- Does it say something, or merely sound impressive?
- Can the nearby visual prove it?

If a line only sounds deep, delete it.
